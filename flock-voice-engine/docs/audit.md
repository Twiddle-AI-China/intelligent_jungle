# 验收判据说明

本文说明 `tools/audit_notes.py` 与 `tools/render_grid.py` 各自量什么、门槛值从哪来、
以及**每条判据抓不住什么**。

## 为什么需要这两个工具

midiBrave 的失效模式不是「不出声」,而是「出声了但错了」。

条件张量拼错一维、note embedding 查错行、velocity 走错档、FiLM 条件没沿时间轴对齐 ——
解码器照样吐出一段听上去像乐器的波形。裸耳听单音很难当场判断音高偏了 40 cents,
更判断不出 velocity 两档是不是接反了。**「看起来在工作但其实是错的」是本项目最大的
质量风险**,这两个工具就是防这个的。

分工:

| 工具 | 产出 | 能回答的问题 |
| --- | --- | --- |
| `audit_notes.py` | markdown 报告 + 每个测试点的 WAV | 音高对不对、力度方向对不对、数值健不健康 |
| `render_grid.py` | 一目录试听 WAV + 连播带 + INDEX.md | 音区一致不一致、音色像不像、尾音干不干净 |

数字能证伪,证明不了「好听」;耳朵能判断好听,判断不出 40 cents 的系统性偏差。
两个都要跑。

## 设计前提:不依赖模型能加载

两个工具都只接一个回调:

```python
render(midi: int, velocity: int, duration: float) -> np.ndarray  # 44.1 kHz mono float
```

模型能不能加载、走的是流式还是离线,与验收器无关。所以**现在就能写完并验完**,
不必等模型接通。接通那一刻把回调指过去即可:

```bash
python3 tools/audit_notes.py --render server.backends.brave:make_render --out-dir staging/audit_brave
```

不给 `--render` 时用内置的正弦波假 render,这是**验检测器本身**的手段(见下)。

## 自测:两层

### 第一层 —— 正弦必须满分

正弦的基频是精确已知的,所以音高一项必须**满分通过**。实测最大残差 **0.096 cents**,
远低于自测断言的 1.0 cent 门槛。如果这里都不满分,真模型跑出来的任何 cents 数字都不可信。

### 第二层 —— 故障注入

**一个永远返回 PASS 的验收器比没有验收器更危险**,它会给错误的实现发一张通行证。
所以自测还手工造出每一种已知故障形态,断言对应闸门必须亮红灯:

| 注入的故障 | 对应的真实 bug | 应被拦下的闸门 | 实测 |
| --- | --- | --- | --- |
| 降八度 | note embedding 查错行 / 频率算错底 | pitch | ✅ |
| 整体失谐 40 cents | 条件时间轴没对齐 / 采样率假设错 | pitch | ✅ |
| velocity 未生效 | velocity 压根没进条件张量 | velocity | ✅ |
| velocity 接反 | 两档 velocity 接反 | velocity | ✅ |
| 输出含 NaN | 数值通路故障 | health | ✅ |
| 输出削顶 | 增益结构错误 | health | ✅ |
| 直流偏置 | 解码器最后一层偏置异常 | health | ✅ |
| 纯噪声 | 条件全错、解码器崩掉 | pitch | ✅ |

```bash
python3 tools/audit_notes.py --self-test    # 两层自测一起跑
python3 tools/render_grid.py --self-test
```

## 判据一:音高准确度

**测法。** 跨训练音域网格 `31 / 36 / 48 / 60 / 72 / 84 / 95`(默认 velocity 127,时长 1.5 s),
每个点实测 f0,与 `440 × 2^((midi−69)/12)` 比,算 cents 误差。

**边界必须踩到。** 训练音域是 31–95(BRIEF.md),分布外的塌陷总是从两端先出现,
所以网格刻意包含 31 与 95,而不只取好看的中间八度点。

**八度错单独统计。** cents 误差先拆成「整八度部分」+「八度内残差」:

```
octaves  = round(cents / 1200)
residual = cents − octaves × 1200
```

八度错和几 cents 的失准是**两种性质完全不同的故障** —— 前者多半是查错行或算错底,
后者是精度问题。混在一个中位数里会互相掩盖:一个八度错(1200 cents)足以把中位数
拖到毫无意义。所以 median/p90 统计的是**残差**,八度错另计一个错误率。

**门槛。**

| 指标 | 参考值(评测报告实测) | 本工具闸门 |
| --- | --- | --- |
| 残差 median | ≈ 7 cents | ≤ 15 cents |
| 残差 p90 | ≈ 17 cents | ≤ 35 cents |
| 八度错误率 | 0 | = 0(不留余量) |

闸门在参考值上留了约 2× 余量,理由:测试点少得多(7 个 vs 全量)、f0 检测器也不是
评测报告用的那一个,复现到小数位没有意义。八度错**不留余量** —— 它不是精度问题,
是逻辑错误,出现一次就说明条件通路接错了。

**f0 检测器。** 优先 `librosa.pyin`(装了就用),没装则退回自带的纯 numpy YIN:
差分函数(FFT 自相关)→ 累积均值归一化 → 阈值取**首个**局部极小 → 抛物线插值。

两个实现细节值得记一笔:

- **取首个谷底而非全局最小。** 全局最小常落在真实周期的整数倍上,直接导致降八度误判。
- **必须做抛物线插值。** 整数 tau 的分辨率在高音区不够 —— note 95(1975 Hz)时相邻
  tau 相差约 50 cents,不插值的话 15 cents 的门槛根本无从谈起。

**搜索区间 40–4200 Hz,刻意开得比训练音域宽**(note 31 ≈ 48.6 Hz,note 95 ≈ 1975 Hz)。
搜索窗若贴着目标音开,八度错会被窗口本身挡在外面而测不出来 —— 而八度错恰恰是条件
接错时最典型的症状。宁可放宽搜索让它暴露。

**取值口径。** 跳过前 15% 的样本(起音瞬态音高本来就不稳,算进去是在惩罚模型本该有的
行为),只统计能量高于峰值 20% 的帧,取**中位数**(对个别跳到谐波上的帧免疫)。

## 判据二:力度单调性

**测法。** 对 note 48 / 60 / 72,分别渲染 v50 与 v127,比 RMS(dBFS)。

**为什么只有两档。** 训练里 velocity 只有 `{50, 127}`(BRIEF.md)。前端三档
(0.42 / 0.68 / 1.0)的映射是 `0.42 → v50`、`0.68 与 1.0 → v127 + 增益差分`,
**禁止插值**。所以验收也只测这两档 —— 测中间值等于测分布外行为,没有参照答案。

**门槛。** v127 的 RMS 至少高出 v50 **0.5 dB**。

- Δ ≈ 0 → velocity 根本没进条件张量(最常见的静默故障)
- Δ < 0 → 两档接反了

**这条判据抓不住什么。** 它只看响度。真实的力度差应当**连音色也变**(高力度更亮、
谐波更丰富),而 RMS 对此完全无感。用一个纯增益冒充 velocity 条件能通过这道闸门。
所以 `render_grid.py` 的 velocity 组必须实际听 —— 听差异是「只有响度」还是「音色也变」。

## 判据三:包络合理性

**测法。** 30 ms 窗 / 5 ms 跳的滑窗 RMS 包络:

- **起音时间** = 包络首次到达峰值的时刻(ms)
- **800 ms 留存比例** = 800 ms 处包络 / 峰值包络

窗口取 30 ms 是个折中:短于此值会被最低音(48.6 Hz,周期 20.6 ms)的单个周期波动带偏,
长于此值则测不准几百毫秒量级的起音。

**对照画像**(dashboard,`--profile` 选用):

| 画像 | 起音 | 800 ms 留存 |
| --- | --- | --- |
| `s001434` | 485 ms | 0.50 |
| `s048091` | 313 ms | 0.73 |

容差:起音 ±40%(相对)、留存 ±0.15(绝对)。不给画像时只报数、不判定。

**⚠️ 这是一道弱闸门,别拿它当音色匹配的证据。** 包络随音高与音色波动很大,容差必须
开得宽才不误报;而已知的两个画像相距不远,容差带是**重叠的** —— 实测中同一段正弦
(357 ms / 0.59)同时「通过」了两个画像。它能抓住的是量级级别的错(起音塌成 0、
留存掉到 0.05),抓不住「像不像这个音色」。后者只能靠听。

留存比例 > 1 是合法的,说明峰值出现在 800 ms 之后 —— 慢起音 pad 的正常形态。

## 判据四:数值健康

在 `nan_to_num` **之前**统计,否则等于把病人治好了再验血。

| 指标 | 门槛 | 触发时说明 |
| --- | --- | --- |
| NaN / Inf | 0 | 数值通路故障,下游一律污染 |
| 削顶样本占比(\|x\| ≥ 0.999) | ≤ 0.1% | 增益结构错误 |
| \|直流偏置\| | ≤ 0.01 | 解码器末层偏置异常;送进前端总线会顶掉动态余量 |
| 峰值 | ≥ 0.01 | 低于此值等于没出声 |

WAV 落盘**不做归一化** —— 削顶要能听见。归一化会把「输出过载」这个故障洗掉,
而那正是要抓的东西之一。

## 试听素材 `render_grid.py`

四组,共 28 个点(默认参数):

| 组 | 内容 | 该听什么 |
| --- | --- | --- |
| `scale` | 八度阶横跨 31–95 | 音区一致性;边界 31/95 有没有塌陷 |
| `melodic` | C 大调音阶(0.8 s) | 旋律语境下的音准 —— 比孤立单音更容易听出问题 |
| `velocity` | 5 个音 × {v50, v127} | 力度差是**只有响度**还是**音色也变** |
| `sustain` | 3 个音 × 6 s | 尾音、循环痕迹、慢性漂移、块边界爆音 |

6 s 是前端 `unperchToRelease` 的 `durationSeconds` 上限,压着上限听。

另出 `contact_sheet.wav`:全部测试点按顺序拼成一条(约 60 s),点间垫 0.35 s 静音。
逐个点开 28 个文件没人受得了,一条连播就能定位到可疑的点再开单个文件。
拼条前会清掉非有限值 —— 一个 NaN 顺着 `concatenate` 会污染整条带,让人误以为整个
音源都坏了;单点 WAV 保持原样,故障留在原处可见。

`INDEX.md` 随目录生成,标注每个文件是什么、该听什么。

## 已知局限(汇总)

1. **包络闸门区分不了相近音色** —— 见判据三。
2. **力度闸门只看响度**,纯增益能骗过它 —— 见判据二。
3. **不判断音质。** 主线权重是 Phase 1(`generator_updates=75365`,
   `discriminator_updates=0`,没跑对抗微调),音质上限本来就有限。验收器只判
   「对不对」,不判「好不好」。
4. **不测时序行为** —— 块边界爆音、underrun、pacing 属于 `tools/smoke_client.py`
   的范围(另一个 agent 负责),这里只测离线单音。
5. **不测多声部。** V1 单声部 pad;voice 池的行绑定、`gate=0` 常驻等问题要等 V2。

## 命令速查

```bash
# 自测(两层:正弦满分 + 故障注入)
python3 tools/audit_notes.py --self-test
python3 tools/render_grid.py --self-test

# 接真模型
python3 tools/audit_notes.py --render <module>:<attr> --out-dir staging/audit_brave --profile s001434
python3 tools/render_grid.py  --render <module>:<attr> --out-dir staging/grid_brave

# 自定义网格 / 画像
python3 tools/audit_notes.py --notes 31,40,55,70,85,95 --duration 2.0
python3 tools/audit_notes.py --expect-attack-ms 400 --expect-retention 0.6
```

退出码:0 = 全部闸门通过,1 = 有闸门未过(可直接用于 CI)。
