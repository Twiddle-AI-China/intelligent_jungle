# 乐理 / Agent / 得分规则评审与优化方向

日期：2026-07-21

基线：`feat/single-tree-ui` @ `a10b9d3`

性质：评审结论与优化候选；P0 三项已于本轮按推荐方案实施，其余未拍板项不冒充现行规则。

## 1. 结论摘要

整体架构是合理的：Master 管和声菜单、flock 管声部行为、world 管生理执行，用音乐单位而非秒做决策，网络失败不阻塞节拍。这些应保留。

本轮已先修三个反馈逻辑矛盾：

1. 合法的纯 color 发音会得 H=0，反而被 Master 当成低分。
2. 相对最响声部的电平最大值必然是 0dB，但满分带上限是 -3dB，因此每天至少一轨必然扣分。
3. tension 在 config 与 policy 有两套实际范围，调参者无法知道哪个生效。

这三项属于 P0 正确性，现已完成并由单元测试与固定 seed 评估锁定。

## 2. 建议保留的规则

### 2.1 决策分层

- Master 是唯一和声作者，flock 不各自定调。
- Master 和 flock 都只在人工限定菜单内决策，输出越界整包回落。
- LLM 是个性层，规则层是可确定性兜底；不等网络才继续运行。
- USER 交回 Agent 后下一拍恢复当日既有 plan，不伪造日结。

### 2.2 音乐时间

- 驻留用拍、活跃窗用小节、pattern 保持用 loop，BPM 变化不改作曲语义。
- 1 loop = 16 步的默认契约与当前 4/4 × 4 小节一致。
- `pitchBranchId` 与 `stepIndex` 分离是正确方向，应继续完成而不应再扩展 Bass 特例。

### 2.3 长时和声结构

“季=单骨架和弦，日=色彩档”能保持身份与声部稳定，与多 loop 乐句保持不冲突。在 Sequence v2 尚未产生足够日内变化前，不建议同时加快根音进行，否则无法判断单调来自节奏还是和声。

## 3. P0 正确性问题

### 3.1 H 的名称与数学含义不一致

修复前公式：

```text
rawH = (skeletonSeconds×1.0 + colorSeconds×0.7 + outsideSeconds×0) / totalSeconds
H = clamp((rawH - 0.7) / 0.3, 0, 1)
```

结果是：纯 skeleton=1，骨架/色彩各半=0.5，纯 color=0。这不是“和谐度”，而是“骨架依附度”。同时 Master 将 H<0.4 与树行为低分同等处理，形成反馈倒置：tension 提高 → color 落枝增多 → H 降低 → Master 认为系统变差。

本轮选择：

- **H 保留 rawH，不做 0.7→0 重标**。这样纯 color=0.7，依然是合法和声；outside 才显著降分。

验收应锁定：纯 skeleton=1、纯 color=0.7、纯 outside=0，无发音=`null`。

### 3.2 相对响度偏好带必然扣一轨

现在以当日最大 RMS 为 0dB 锚，满分带却是 -24–-3dB。最响声部每天必然越过上限。

已完成第一步，第二步留作候选：

1. 短期将上限改为 0dB，使该维度只惩罚过静声部；clip 仍由 peak 独立告警。
2. 如产品确实要惩罚“一轨压住其他轨”，应新增全局 dominance 指标（如轨道 RMS 占比/中位数偏差），而不是惩罚必然存在的 0dB 锚。

修改前后应用固定录音重算四轨分布，不凭听感直接拍阈值。

### 3.3 tension 存在两个事实源

- 修复前 `config.harmony.tensionBase/Peak` 定义 0.2→0.6。
- 修复前 `master/policy.js` 直接用季内进度生成 0→1，而 policy 几乎每天都返回 tension，因此 config 范围通常不生效。

已将 `tensionRange=[0.2,0.6]` 放入 Master menu，policy / LLM / external 共用范围校验；旧菜单缺字段时仍兼容 0..1。

固定 seed `20260721`、16 天评估中，F 档 H 均值为 0.9323，未再出现合法 color 被压成 0 的倒置；302 项 MVP 测试全绿。评估同时暴露一个独立遗留问题：F 档 `densityComplementarity=0.002`、`conflictRatio=0.9961`，支持下文将 crossVoice 重构为真正的合奏冲突判定，而不是继续调 H。

## 4. P1 规则优化

### 4.1 Agent 还没有时间维决策权

Agent 虽已能看到 `sequencePattern`，输出却仍是家枝 `{from,to}`。`activeBars` 也只能“从第 0 小节起硬截断”，无法表达第 2、4 小节活跃或切分节奏。

优化方向：

- 用 cell mutation 或 `activeStepMask[16]` 替代只有长度的 activeBars。
- 物种差异变成网格约束：Pad 延音/复音，Melody 稀疏单音/邻接运动，Bass 低音级/稳定循环，Texture 概率稀疏。
- 每日变异保留“最多 2 个小改动”的可听稳定性，但上限应按 cell 数而不是鸟数定义。

### 4.2 规则层依次修正可能互相覆盖

当前 `evaluateDay` 顺序处理驻留、换枝、crossVoice，后一段可再改前一段的 dwell/density/activeBars。代码有部分防抵消守卫，但解释仍依赖执行顺序。

建议先产生独立 suggestions，再用一个显式 resolver 合并：

```text
安全下限 > USER/Master 所有权 > 纠正严重偏离 > 保持稳定 > 风格小变
```

时间线应显示“观测 → 建议 → 最终合并”，这也是分数 tooltip 应共用的可解释数据。

### 4.3 crossVoice 把三轨同时发音一律当冲突（已修正）

当前每个半拍 bin 中：0 轨=blank，1–2 轨=complementary，3–4 轨=conflict。这会鼓励编曲长期只有一两轨，而不是判断三轨是否真的频谱/音区冲突。

同时 `crossVoice` 是一个全局值，却被相同地计入四棵树的得分；虽然 bias hint 会轮换抑制者，分数本身不能说明哪轨需调整。

已落地：

- perch 改为半拍起音 gate，unperch/长栖不再把持续音扩成整日冲突。
- 允许 3–4 轨并行；同 gate 内至少 3 轨且最近轨间音区 <5 半音才判冲突（无 midi 时仅四轨全齐保守判冲突）。
- economy 显示每轨自身活跃 gate 的质量，bias 优先按真实冲突贡献轮换 suppress；静音轨豁免。
- headless evaluator 共用相同口径。固定 seed `20260721`×16 天：F `densityComplementarity 0.002→0.7756`，`conflictRatio 0.9961→0.0059`。

尚未加入的精细化：起音瞬时响度尚无事件级采样，因此当前冲突门只用密度+音区，日 RMS 仍由独立 loudnessBalance 评分。

### 4.4 Bass 的节奏行为没有被 branchChanges 捕获（已完成）

Bass 的 `branchChanges` 权重已改为 0，只保留诊断；正式行为维改为：

- 唯一起音步数 2–5 / loop，权重 0.55；同一步复音只算一个有效起音。
- 循环间隔规律度 `1/(1+CV)`，满分带 0.55–1，权重 0.45。
- 规则/LLM Agent 消费两项偏离：起音偏离调密度/窗口；规律度偏低时将一个密集 cell 移到最大循环空隙，保持 cell 数不变。

### 4.5 cohortSize 只看单日峰值，对瞬时波动过敏（已完成）

`cohortSize` 得分现使用同枝负载的时间加权 P90；瞬时 peak 独立保留并在超过物种上限时显示告警。短于全天 10% 的扎堆不再单独定义全天习性分。

### 4.6 evaluator 的全指标 `F≥C≥R` 假设不成立（已完成）

R 可能随机命中级进/密度统计，C 的静态默认值也可能比会主动调整的 F 更贴偏好带；因此全指标机械排序不是有效验收。

现改为机制专项闸门：H 允许小容差但不得明显退化，F 的 Sequence 贴拍必须相对 C 显著改善，行为/合奏/旋律设绝对健康下限，冲突/空白/可听具身损失设安全上限；R 只保留诊断展示。

固定 `seed=20260721`、16 天回归已通过全部 9 个 gate：F 行为健康 0.8213、Sequence 贴拍 0.9406、合奏互补 0.7339、冲突 0.0255、空白 0.2118；Bass 日均起音 2.8125、间隔规律度 0.6237、群聚 P90 2.0，均落入当前可达范围。

## 5. P2 乐理丰富度与 Master USER

### 5.1 季长 8–16 天是可用先验，不是已验证最优值

单骨架长季的优点是身份稳定，风险是听感疲劳。建议先完成 Sequence cell 变异，然后做固定 seed 的 8/12/16 天 A/B，比较：

- pattern 相似度与变化率；
- 四声部占空/空白分布；
- H 与行为分分布；
- 盲听下的新鲜、连贯、过渡是否过于频繁。

若仍单调，先增加季内 color cadence / inversion / register 变化，不立即引入第二根音。

### 5.2 “和弦走向”需先定义编辑层级

Master USER 中的“和弦走向”有两种完全不同的产品语义：

1. 编辑一年的四季骨架顺序，仍保持季内单和弦。
2. 允许在单季内编辑多和弦进行。

推荐先实现 1，因为它不破坏现有季节/家枝迁移契约。2 应作为独立乐理版本，需重新定义迁移、holdLoops 与 H，不应偷渡成一个 HUD 选项。

## 6. 建议的分数信息架构

为了避免“一个数字同时表示习性、响度、合奏、和声”，建议最终拆成：

| 层 | 含义 | 建议组成 |
|---|---|---|
| 声部习性分 | 这棵树是否像它自己 | 非 Bass：branchChanges；Bass：onsetCount / intervalRegularity；共同含 meanDwell / cohort P90 |
| 声部电平健康 | 是否过静/削波 | quiet-floor 分 + clip 告警，不与风格混为一个原因 |
| 全局合奏分 | 四轨是否在时间/音区/响度上互补 | 独立 crossVoice / dominance，再给每轨贡献提示 |
| 和声观测 | 落音是否在 skeleton/color 框架内 | raw H，未拍板前不进 economy 总分 |

第一轮不必立即变更侧栏的主总分；可先用 tooltip 按这个层级展示旧分数，同时记录新旧两套分布，再决定是否改主分。

## 7. 验证方法

任何规则优化不只看单元测试，应固定 seed 跑至少 16 天并保存日摘要：

- 每轨有效指标原始值、单项分、总分、H；
- Sequence 占位率、重复率、相似度、同步冲突；
- Master 的 color/tension/换季决策与触发证据；
- USER 介入前后的恢复时间和分数变化。

闸门：没有新的必然扣分、没有 tension→H 反向闭环、四轨不被长期压成两轨、无声观测仍为 `null` 而不是 0。
