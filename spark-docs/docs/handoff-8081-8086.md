## 1. 8081 API 调用要点

OpenAI 兼容,无鉴权,浏览器可跨域直调。健康检查 `GET /v1/models`。

- **非流式**:POST `/v1/chat/completions`,body 带 `model/messages/temperature/max_tokens`,读 `choices[0].message.content` 与 `usage`。
- **流式(SSE)**:加 `stream:true` + `stream_options:{include_usage:true}`。**三个坑**:① 客户端必须缓冲原始字节流、`TextDecoder` 带 `{stream:true}`,中文多字节字符会跨 TCP 包;② `finish_reason="length"` = 被 max_tokens 截断;③ `delta.content` 首尾包可能为空,要判空。
- **采样**:agent/结构化任务 `temperature=0`;`max_tokens` 给足(结构化建议 512–1024)。
- 服务端已开**前缀缓存**(~50% 命中):长 system prompt 每次重复发几乎免费,调用方不要做拼接去重。
- **重试**:请求幂等,60 s 超时 + 3 s 退避即可。
- 完整示例(JS fetch / 流式解析 / 错误表)见仓库 `api_8081.md`,本文不重复。

## 2. 核心方法论:如何让 8081 快速且稳定输出 JSON

这套结论是 2026-07-18 在 Prompt Lab(8086)上几十组对照实验试出来的,每一步都有实测数据。

### 2.1 问题起点

Step3-VL-10B 是推理模型,默认先输出几百上千 token 的 `<think>` 自由推理,agent 高频调用完全不可用。目标是:**只输出一个合法、结构固定、语义正确的 JSON 对象,且不带思考**。

### 2.2 铁律一:必须用 `json_schema`,不要单独用 `json_object`

- `json_object` 只约束「输出是合法 JSON」。实测当输入里有大段 JSON(比如状态对象,尤其内含长得像答案的子结构)时,模型会**把输入原样复读出来**——锚定效应,temperature=0 下 100% 复现;改 prompt 结构、加 few-shot 示例均无效。
- `json_schema` 是逐 token 的语法级约束(后端 xgrammar),结构直接被锁死,复读从根上不可能,同时顺手消灭 CoT:

```json
"response_format": {"type": "json_schema",
  "json_schema": {"name": "decision", "schema": { ... }}}
```

### 2.3 铁律二:schema 的字段顺序是行为开关

引导解码**按 `properties` 的书写顺序生成**,顺序直接改变模型行为:

- **自由文本字段(如 reason)放最前** = mini-CoT:模型先「说」一句理由,后面的枚举和数值会跟理由保持一致,语义正确率显著提升。
- **枚举/编号类字段绝不能放第一位**——会被第一个枚举值锚定(实测 rule 编号放首位时,所有输入都被判成同一个规则);也不要紧跟在自由文本之后。**放最后一位当事后标签**最稳。
- `required` 要列全,模型不会自己「省略」字段;可空字段写 `anyOf: [{...}, {"type":"null"}]`。

样板(实测定稿的结构):

```json
{"type": "object",
 "properties": {
   "reason": {"type": "string",
              "pattern": "^[\\u4e00-\\u9fa50-9\\uff0c\\u3002\\u3001\\uff1b\\uff1a]{4,30}$"},
   "weights": {"type": "object",
               "properties": {"a": {"type": "number"}, "b": {"type": "number"}},
               "required": ["a", "b"], "additionalProperties": false},
   "mode":   {"enum": ["x", "y", "z"]},
   "target": {"anyOf": [{"type": "object",
                         "properties": {"x": {"type": "number"}, "y": {"type": "number"}},
                         "required": ["x", "y"], "additionalProperties": false},
                        {"type": "null"}]},
   "rule":   {"type": "integer", "enum": [1, 2, 3, 4, 5, 6, 7, 8]}
 },
 "required": ["reason", "weights", "mode", "target", "rule"],
 "additionalProperties": false}
```

### 2.4 铁律三:自由文本字段用 `pattern` 限长,禁用 `maxLength`

模型会把自由文本字段当分析通道,枚举式啰嗦到撑爆 max_tokens(输出截断成废文)。正确做法是从生成起始就约束字符集和长度,模型自然写短句(见 §2.3 样板的 `reason`):4~30 个中文/数字/标点,禁英文——防止照抄输入里的英文字段名。

**反面教材:`maxLength` 硬截断会诱发无限空白循环**(模型写到一半被掐断,随后只会输出合法 JSON 空白直到 max_tokens),千万别用。

### 2.5 prompt 怎么写(配合 schema 才生效)

1. **任务里只做优先级和映射,不做数值推理**。10B 模型对「某值 > 6 就…」这类数值阈值判断极不可靠(阈值写在 prompt 里也会漏判)。把阈值/几何判断在调用方预计算成布尔开关(如 `flags.xxx=true`)和预计算坐标,放进输入 JSON;模型只回答「哪个开关为真 → 做哪档动作」。
2. **规则 ≤8 条**,编号即优先级;实测 7~8 条稳定,再多优先级会乱。
3. **数值用「方向 + clamp」表达**(「提高」「降一档」),不要写精确等式要求;越界值由调用方截断。
4. **不要给模型超出能力的知识要求**——规则只用模型能理解的领域语言。
5. 输出要求写清:只输出一个 JSON 对象、字段有哪些、枚举取值集合。

### 2.6 实测效果(这套组合的最终形态)

- ~1250 tok 输入 / ~80 tok 输出 / **2.2–3.0 s** 返回合法决策 JSON;一组 8 场景回归用例结构校验 8/8、语义校验 8/8。

## 4. 8081 性能工程:投机解码实验(结论:不启用)

背景:单卡单 GPU,TP/DP/PP 都需要 ≥2 个计算设备,单流 ~40 tok/s 是显存带宽瓶颈(每 token 读完全部 9.7 GiB 权重),并行架构无解。唯一对单流有效的杠杆是投机解码,实测(测试容器 @8087,与生产互斥):

| 场景 | 基线 | n-gram 投机 | 变化 |
|---|---|---|---|
| 单流 decode(短/中/长 prompt) | 40.8 / 40.5 / 38.7 tok/s | 50.6 / 53.0 / 62.6 tok/s | **+24% / +31% / +62%** |
| 并发 2/4/8 聚合 | 85 / 170 / 327 tok/s | 92 / 179 / 344 tok/s | +5~8% |
| 并发 16 聚合 | 637 tok/s | 536 tok/s | **−16%** |
| JSON 决策请求 | 2.2–2.4 s | 1.0–1.5 s(接受长度 4.83,接受率 88%) | **~1.8×** |

但发现 **投机 × json_schema 组合在特定输入下确定性触发空白循环**(5/5 复现,调参数不治);解法 `--structured-outputs-config '{"backend":"xgrammar","disable_any_whitespace":true}'` 实测有效——**这个开关本身值得记住,它能从语法层根治一切「空白循环」类截断失败**。

最终决策(2026-07-19):**生产 8081 不启用投机解码,维持原配置**。复现方式:`start_vllm_step3vl_ct_spec.sh`(注意与生产互斥,实验前须先停生产)。配置键名是 `num_speculative_tokens`(不是 num_spec_tokens);vllm-openai 镜像 entrypoint 已含 `serve`,启动命令直接跟 `/model`。

## 7. 踩坑清单(速查)

1. `json_object` + 大 JSON 输入 → 原样复读;必须 `json_schema`。
2. schema 字段顺序是行为开关:自由文本最前、枚举最后。
3. 自由文本用 `pattern` 限长;`maxLength` 硬截断 → 无限空白循环。
4. 数值阈值判断不可靠 → 调用方预计算成布尔开关。
5. 规则 ≤8 条;数值用方向+clamp,不写等式。
6. 投机×json_schema → 空白循环;`disable_any_whitespace` 根治。
7. 流式客户端必须整流缓冲 + `{stream:true}`,否则中文乱码。
8. 投机解码配置键名 `num_speculative_tokens`;镜像 entrypoint 已含 `serve`。
9. nvidia-smi 在 GB10 上字段不可用;显存常驻 97 GiB 是预分配不是泄漏。
