# Phase 4 交互设计：USER 接管与树特写（已对齐 2026-07-19）

状态：**已对齐，待实施**。对齐结果：两档控制权；USER 档树照常生存计分、无豁免；不造写谱器 UI，点选枝直接放鸟。

## 1. 设计原则

用户不是在操作音序器，是在**和鸟群相处**。不直接指定音符——点的是枝，音高由「枝=音」映射+当日色彩档翻译，怎么点都在和声内。

## 2. 两档控制权（与 zoom 绑定，无手动开关）

**回退全窗口（2×2）= 全部树 AGENT 完全接管；进入某树特写 = 该树 USER 接管。**
不存在单独的切换钮——zoom 状态就是档位状态。

| 状态 | 语义 | agent 行为 |
|---|---|---|
| 全窗口 | 现状全自动 | 四树照常 |
| 某树特写 | 该树 USER：停计划/变异 | **回退全窗口后该树回 AGENT，且 agent 根据用户给的继续**——用户摆的鸟就是现状（家枝/栖位即 world 状态），plan 在现状上推演，不主动重置/回滚用户布局 |

USER 档的树照常生存：吃生态计分、吃 master 框架、换季照样被迁移。树死树活都是用户造成的，无豁免。

## 3. USER 档交互（不造新 UI，就现在这套）

- 点某根枝 = **把一只鸟放到那根枝上**（立即栖息→立即发音；树上有空位鸟就上，没有则替换最远停留最久那只）；长驻型声部（pad/bass）按住=持续，点击型（melody/texture）点一次发一句/一簇（沿用音色 v3 的发声形态）；
- 点已栖枝上的鸟 = 赶走（离枝）；
- **树特写（zoom）**：点树卡片/树身，该树放大占满舞台，其余三树缩边缘继续演奏降混响；特写里点枝更精确，处理密枝/低枝；退出回 2×2。特写是交互的视口放大，不是新模式。

## 4. 与现有系统的接缝

- 点选落枝/赶走：走 world 现有的 perch/unperch 路径（用户=一个特殊的「手」源，事件带 cause:'user'），音频/计分/生态观测零改动全部自动生效——这正是「无豁免」的实现方式：用户摆出的行为照样进换枝率/驻留/群聚/H；
- AGENT 树完全不受影响；
- 交回 AGENT 时 agent 从用户摆的局继续演化（不主动抹掉用户布局）。

## 5. 概念清点

新增 2：两档控制权（标志位）、user 事件源。删除 0。净增 2。

## 6. 验收

- 点枝→该枝立刻有鸟有音；赶走→立刻消声（长驻型）；
- USER 树侧栏长势/H/换枝统计照常滚动，值由用户行为决定；
- 换季时 USER 树照样被 master 大迁移（用户布局被生态收编）；
- zoom 进出流畅，其余三树演奏不中断。
