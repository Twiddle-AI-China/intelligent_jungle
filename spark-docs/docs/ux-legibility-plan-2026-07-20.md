# UX 可读性与交互可见性计划（2026-07-20，based on Downloads/现存的问题.txt）

> 阶段转向：机制已经过 T0-T4 减法拨回涌现（c8e26a9）；本阶段解决「新用户一眼茫然、
> 看不出能交互、信息太密」——让好机制变得可读、可玩、可探索。纯前端为主，不动生态机制。

## 江南反馈原文归纳（6 点）
1. UI 信息密度太高；美术风格让人看不出哪里可交互、不知道能控制鸟；右侧"日志"太多。
2. 不理解 agent 控鸟逻辑 → 可给说明但**非必要**。
3. 不明白接管 agent 后如何手动控鸟 → 需引导教学。
4. 基础功能（音量/EQ）不该在二级菜单；缺电平表/solo/mute；可放右侧"树·点名特写"轨道（不破坏生态概念）。
5. 鸟位置↔声音联系不明显 → 需电平表/solo/mute 供探索。
6. 长势分数不醒目；机制显示太繁杂 → 直观化：昼夜交替=一轮 pattern（天空日月绕环视觉，非右上角大段文字，手撕日历式）、季节=和弦色彩（大 UI 和弦名，手绘+季节字体）、日志默认隐藏。

## 三条工作流

### WS-1 · 一眼可读：收敛信息 + 视觉语言（point 1、6；纯前端 renderer/index/main/timeline）
- **日志默认折叠**：右侧"决策日志"整块默认收起（留一个小入口可展开）；决策时间线精简保留。
- **昼夜搬到天空**：太阳/月亮沿弧线过顶 = 昼夜交替 = 一轮 pattern（**复用已有 celestial 天体**：config.visual.celestialArc* + renderer 已画日月）。强化其显著度，让"一天=一循环"从天空直接读到。
- **移除右上角大段 transport 文字**，改极简。
- **手撕日历**：day 用手撕日历卡片（大数字=第几天，小字=拍/pattern 进度），按重要度排大小。
- **和弦名称大 UI**：季节色彩=大字和弦名（手绘风+季节特征字体），替代当前小字。
- **长势分数更醒目**：提升 eco 分视觉权重（不再淹没在文字里）。

### WS-2 · 交互可见 + 控制引导（point 3、4、5；前端 + audio 少量接线）
- **"能控制鸟"一眼可见**：树卡片/树本身加可点击 affordance（hover/描边/图标），让"点树接管"自明。
- **首次极简引导 overlay**：1-2 步（"① 点一棵树接管 → ② 点枝放鸟/点鸟赶走"），可跳过、不再弹。
- **基础功能上提为"声部轨道"**：把 mix-panel 二级菜单并入右侧"树·点名特写"——每声部一行 mixer 轨=【名称 + 电平表 + solo + mute + 音量(+EQ 展开)】。既是控制台又是"鸟位↔声音"探索器（solo 单听某树、看电平表随鸟发声跳动）。audio 已有 MIX_PARAM_SPECS/getAudioLevels，可加 per-voice mute/solo + 电平表。

### WS-3 · （可选·低优）agent 控鸟逻辑说明（point 2）
- 江南明说非必要。放最后或只做一句 tooltip；不投入。

## 需江南拍板的叉
A. **优先级**：先 WS-1（视觉语言/可读，纯前端见效快、直接治"一眼茫然"）还是 WS-2（控制/探索，功能更重）？
B. **solo/mute/电平表落点**：确认做成"点名特写"里每声部一行的 mixer 轨（含电平表/solo/mute/音量），把现有 mix-panel 并进去？
C. **引导形式**：首次 overlay 引导 / 常驻视觉 affordance / 两者都要？

## 边界与纪律
- 不动生态机制（world/economy/agent/mapping/harmony 决策逻辑）；本阶段是 index.html/main.js/renderer.js/timeline.js + audio.js（仅 mute/solo/level 接线）。
- 美术三 token 克制不变（paper/ink/accent）；手绘/季节字体在此框架内。
- codex 不可用（额度到 Jul 25）→ 派 cursor/kimi。
