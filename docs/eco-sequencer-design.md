# 生态音序器 v3：四树四声部

> 状态：设计稿（2026-07-18，v3）。取代 v2 的「抽象栖木」方案。
> 飞书同步：https://twiddle-ai.feishu.cn/docx/IKXCdw0GUoRzKOxem3OcMvpqnyh
> 变更来源：v2 评审反馈——规则太多；具象化为「4 群鸟 × 4 棵树」。

## 0. 原则

1. **agent 是生物，不是作曲家**——目标函数只用生存词汇定义，音乐是副产品。（不变）
2. **生态要成为音序机制本身**，不能只是视觉皮肤。（不变）
3. **做减法**（v3 新增）：凡是 30 秒 demo 里观众看不见、听不出的机制，一律砍掉。
   v2 的食物/能量税/天敌全部移出黑客松，8 条规则减到 5 条，master 指令收敛到 4 个（§6）。

## 1. 世界 = 四棵树

4 群鸟栖居在 4 棵树上，**一棵树 = 一个声部/乐器**。树是乐器，鸟群是演奏者，
agent 是鸟群的本能。对应现有 4 flock/SPECIES 配置：

| 树 | 鸟种 | 角色 | 声音性格 | 活动时段（chronotype） |
|-|-|-|-|-|
| 低吟树 | 鹈鹕 | bass | 少而重的长低音 | 黄昏最活跃 |
| 和鸣树 | 斑鸠 | support | 持续的咕鸣铺底（pad） | 全天平稳 |
| 飞羽树 | 百灵 | ornament | 高音快旋律（lead） | 清晨最活跃（晨鸣主角） |
| 微光树 | 啄木鸟 | shimmer | 音高化的短促敲击（pluck） | 白天最活跃 |

- **鸟种差异 = 生命属性差异**：活动时段、栖息倾向、飞行性格（速度/紧密度基线）、
  能量消耗率。四个 chronotype 错开 → 一天之内声部自然轮替，编曲对位从生态属性涌现，
  不需要任何编排指令。
- 啄木鸟声部是**音高化短音**（合成 pluck），不是采样鼓——鼓 lane 仍维持已删除状态。

## 2. 树 = 乐器：枝干即音符行

树的形态由和声直接生成，树本身就是可视化的乐谱：

- **枝干 = 和弦内音**：该声部音域带（`bandForChord`）内的每个和弦内音长一根枝干，
  枝干高度 ∝ 音高。枝干只长在和弦内音上——「怎么落都不难听」的和声安全保证，不变。
- **沿枝方向 = 循环时间轴**：枝干从树干伸出的方向即 loop 的 16 步格点。
  一棵树的树冠 = 这个声部的钢琴卷帘。
- **鸟落枝 = 音符**：落点 (枝干, 步位) → (midi, beat)；同一落点的鸟数 → 力度（上限 3 只，
  力度三档）；驻留时长 → 时值。0 只鸟 → 这个音不存在。空树静默。
- **换季（换和弦）→ 枝干重构**：枝干生长/收缩到新和弦内音位置，已栖的鸟就近换枝
  ——即现有的 chord-change requantize 逻辑，只是有了形体。
- **扫描线 = 一缕光/风扫过树冠**：扫到的枝干发亮、栖鸟振翅鸣叫 → 触发音符。
  时钟仍在 transport（G1 采样级节拍精度、G2 扫描线因果，均不变）。
- **引导/驱赶鸟群 = 实时编曲**：把鸟从低音枝赶到高音枝，编曲随之改变。
  没有「接管」按钮，没有拖 anchor——v2 已定的方向，落在树上更直观。

## 3. boids 去哪了：一套鸟群的三重身份

v2 遗留的「两套模拟」问题（world.js 与 instrument/boids.js 各跑一套）在 v3 彻底消失：
**只有一个世界**，每群鸟绕自己的树生活，一部分栖着、一部分飞着。

同一套 boids 承担三重身份：

1. **栖着的鸟 = 乐谱**——音符的存亡/力度/时值（§2）。
2. **飞着的鸟 = 音色**——环绕树冠的「光环」。8D 关系 → 合成器参数的映射原样保留：
   紧密度→滤波亮度、对齐→失谐、扩张→空间感、动能→电平、环流→共振。
   光环躁动，音色就亮而毛糙；光环安静，音色就暗而柔。
3. **起落 = 编曲的变化**——agent 旋钮、昼夜、用户引导改变栖/飞比例，音符随之增减。

**Instrument 层 = 镜头贴近这棵树**，不是另一个页面、另一个模拟：

- camera = {cx, cy, scale}，单 canvas，双击某树 → 镜头向树冠插值跟随；
  u ∈ [0,1] 归一化 zoom 进度，驱动 LOD 交叉淡化（其他树退为远景暗影，本树枝干
  显出音高标注、鸟显出个体）与 UI 面板透明度——连续变化，不是 DOM 显隐。
- **近景交互**：
  - 键盘 A..K = **召唤**：按键 → 一只飞鸟落到对应枝干的当前拍位 = 录音环写谱（G5）。
    声音即时发出（演奏延迟不可接受），鸟随后飞落完成「写谱」动画（声音即时、动画追认）。
  - 拖拽 = 塑形光环 → 音色（沿用现有 motion 控制）。
- **状态机由 u 对齐**：u > 0.5 进入引擎层语义（键盘、录音环、隐含接管）；
  u 回 0 自动交还——顺带修复「返回不交还」bug。音频连续性天然成立。

## 4. 昼夜与四季：自然 = master 的乐器

昼夜和四季定义的全部是**音乐性的东西**，但语义完全是自然的：

- **季节 = 和声色彩**：春=大三（明亮）、夏=sus4（张力）、秋=小七（雾霭）、冬=小三（幽暗），
  可叠加根音移调。换季 → 枝干重构 + 世界色调/枝叶变化。
- **昼夜 = 音色宏 + 密度**：入夜 → 低通变暗、混响加深、多数鸟归栖入眠（音稀而长）；
  白天 → 明亮活跃。一个昼夜 = 8–16 bar（可由 master 调）。
- **晨鸣（dawn chorus）**：每个黎明各群短暂齐活跃——真实鸟类学现象，免费的每日高潮，
  自动的段落结构。
- 四个鸟种的 chronotype（§1）错开 → 一天内声部自然轮替：清晨百灵领奏、白天啄木鸟
  点缀、黄昏鹈鹕低音渐厚、夜里斑鸠独守。

用户在 HUD 改和声/BPM = 人工干预气候，语义与 master 一致。

## 5. Agent：目标是让生态活下去

### 5.1 生态生命值 HP——全场唯一记分牌

| 方向 | 条件 |
|-|-|
| **+** | 四树皆有活动（每 loop 每树至少发声）；力度与音区分布均衡；昼夜节律被遵守（夜里安静）；邻树应答（一树活跃后邻树响应） |
| **−** | 某树长期静默（鸟全飞走/全睡）；总遮蔽超阈（四树同时全密 = 都在吵）；某树种群过密或过疏 |

HP 低 → 世界视觉枯萎、混响变干、整体渐弱；HP 归零不判负，进入「寒冬」等 master 救场
（换季 + 补鸟——音乐上正好是一次转段）。

**关键论断（回答「agent 的目标是什么」）**：HP 的每一项都是「良好编曲的生态化表述」
——均衡=配器、应答=对位、节律=段落、不遮蔽=频段分离。和声安全在更底层已由枝干保证
（§2）。所以 agent 不需要懂音乐、不追求「好听」：**规则本身就是音乐的**，
agent 只要让生态健康，出来的必然是成立的音乐。

### 5.2 种群 agent（每树一个，本地 LLM，每 1–2 bar）

5 条规则（v2 的 8 条合并精简），按优先级：

| # | 生存规则 | 音乐后果 |
|-|-|-|
| 1 | 昼夜作息：按本种 chronotype 决定栖/飞比例 | 声部轮替、A/B 段 |
| 2 | 体力管理：energy 低 → 归栖休息；充沛 → 活跃 | 密度呼吸（纯生理） |
| 3 | 守域：质心保持在己树/己音域带 | 音区稳定、声部分层 |
| 4 | 应答：邻树近期高活跃 → 短暂兴奋 | call-and-response |
| 5 | 兜底：cruise，小游走 | 稳定持续声部 |

- **旋钮不变**：set_motion（三力权重）/ set_density（栖飞比与占枝档位）/ set_anchor
  （树冠内目标区）——映射到现有 Agent Control API，**玮圣接口不用改**。
- energy 简化为单标量，仅由昼夜 + 发声活动驱动（发声耗能、静默回能），
  不再有食物/税输入。
- **G7 韧性不变**：5 条规则同时以纯代码确定性策略实现兜底；LLM 是「个性层」，
  掉线时代码无缝接管，循环永不停。

### 5.3 Master agent（云端强模型，每 4 bar）＝ 自然

只动环境，永不直接碰种群参数（分层不变）。指令收敛到 4 个：

| 指令 | 语义 | 音乐后果 |
|-|-|-|
| `set_population(flock, ±n)`（新增） | 补鸟/减鸟 | 声部厚薄 |
| `set_daynight(bars)`（新增） | 昼夜周期长度 | 段落速度 |
| `set_scale`（既有） | 换季 | 和声色彩/移调 |
| `set_bpm`（既有） | 气温 | 速度 |

目标：HP 最大化。强制 JSON、bar 边界队列、调用预算——均沿用 v2 已定方案。

## 6. 砍掉了什么（回应「规则太多」）

| 条目 | v2 | v3 | 理由 |
|-|-|-|-|
| 食物/投食 | P4 | **砍** | master 抓手改为 population，更直观；「密度收放」后果已被昼夜+HP 覆盖 |
| 能量税 | P3 | **砍** | 同上，重复机制 |
| 天敌 | 阶段 2 | **砍出黑客松** | 事件层锦上添花，30 秒 demo 讲不清 |
| 种群规则 | 8 条 | **5 条** | 安全/饥饿/稳态三条并入作息与体力 |
| 能量经济 | 食物+税+代谢 | **单标量**（昼夜+活动） | 输入源砍掉后自然简化 |
| master 指令 | 7 个 | **4 个** | 只留观众能看见听出后果的 |
| 进化层 | 长线 | 长线（不变） | — |

判据统一：机制的后果必须在画面和声音上双重可感，否则删。

## 8. 开放问题

1. 同一 (枝干, 步位) 的容量：倾向 3 只封顶、力度三档，防止「全堆一个音」。
2. 夜间静默占比：太长 demo 冷场。倾向昼夜周期偏短（8–16 bar），夜里留斑鸠独奏不全静。
3. 枝干数量上限：和弦内音 × 音域带可能出 8–12 根枝，视觉上是否需要按八度合并显示。
4. 驱赶手势的具体形式（点击惊飞 / 拖拽气流），需要原型试玩定。
