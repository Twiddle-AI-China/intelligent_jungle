# 生态音序器：玩法与 Agent 游戏规则（v2 设计）

> 2026-07-18。本文回答三个问题：玩法如何真正贴合生命/鸟群/自然；agent 的行动目标是什么；
> 两个 view 如何变成一体的 zoom。并对照评审《生态系统音序器 · 双层 Agent 规则设计》
> （下称「规则设计稿」），逐条给出采用/修改/不采用结论。
> 上游文档：[PRD](prd-flock-sequencer.md)、[双层架构](two-layer-architecture.md)。

## 0. 一个判断，三个推论

**判断**：好听是底层音乐性的责任，不是 agent 的责任。和弦内量化、音域带、微变化预算已经保证
「无论鸟怎么飞都不难听」。因此：

1. **agent 是生物，不是作曲家**——它的目标函数只能用生存词汇定义（能量、领地、安全、应答），
   音乐是运动的副产品。这与规则设计稿的核心原则完全一致，作为两文的共同公理。
2. **生态要成为音序机制本身**，不能只是视觉皮肤。现在的「固定 pattern + 装饰性漂移」里，
   鸟死了音乐照响——这说明生命还没参与发声。
3. **两层是一个世界的两个焦距**，不是两个页面。摄像机拉近就是下潜。

## 1. 当前实现 review（保留 / 问题）

**保留的骨架**：双层结构、下潜即接管、和声安全（量化+音域带随根音移调）、微变化预算
（漂移→swing/借音，无注入随机）、agent 命令 bar 边界生效、录音环回写、Web Audio 轻量合成器
（Spark 上线后切回 neural decoder，映射契约不变）。

**实锤问题**：
- 返回编排层没有自动交还（`exitInstrument` 缺 `release`），agent 永远不恢复；
- score view 的 anchor 拖拽依赖已删除的接管按钮留下的状态泄漏，是死路径；
- score 层和 instrument 层是**两套独立的鸟群模拟**（world.js 2D 7 鸟 vs instrument/boids.js
  3D 18 鸟），下潜后看到的不是刚才那群鸟——「两个页面感」的根源；
- score view 玩法太薄：观看、改 HUD、下潜，仅此而已。

## 2. 玩法核心：栖木音序（perch sequencing）

把「音符=栖木」定为编排层的核心机制。这是对规则设计稿「停步=长音」思想的采用，
但触发时钟保留在扫描线上（原因见 §6 评审表第 2 条）。

- **栖木 = anchor**：乐句定义栖木的位置（beat × 和弦内音 × 音域带内）。栖木永远落在
  和弦内音上——这就是「怎么飞都不难听」的保证，不变。
- **鸟的停驻决定音的存亡与力度**：每只鸟分配到一个栖木（现有 `bird.id % anchors.length`）。
  扫描线扫过栖木时：
  - `力度 = 停驻鸟数 / 分配鸟数`（停驻 = 距栖木 r 内）；
  - 0 只鸟停驻 → 这个音**不发声**；
  - 停驻稳定（驻留时间长）→ 长音（durBeats 延长）；掠过 → 短音。
- **用户在编排层的自然玩法**：引导（吸引/驱赶）鸟群 = 实时改编曲。把鸟从一片栖木赶走，
  那些音自然消失；把鸟聚到高音区栖木，高音变强。**不需要「接管」按钮，不需要拖 anchor**
  ——拖拽死路径顺势删除，接管概念只在下潜时隐含存在。
- **微变化预算不变**：停驻鸟群的均值漂移仍折算 swing/借音。

音乐性由此从生态涌现：密度=占用率，力度=停驻数，长短=驻留时间，起伏=能量（§3），
而每个可能发出的音仍被和声安全钳制。

## 3. 代谢：能量、昼夜、季节

采用规则设计稿的能量经济，映射到现有字段：

- **能量**（`voice.energy` 重定义为代谢库存）：发声耗能（∝力度），静默回能，
  master 可征 energy_tax，吃到食物 +E。
- **能量→行为**：低于阈值 → 栖息比升高（音变疏、变长，声部「休息」）；充沛 → 活跃。
  总输出电平乘 energy（已有 `level = 0.35 + energy*0.65`）。段落呼吸从代谢涌现，
  不需要任何「编排结构」指令。
- **昼夜**：master 广播昼夜相位（每 N 个 loop 一昼夜）。夜间世界变暗、回能、活动下降
  ——自动的 A/B 段。
- **季节 = 和声**：master 换根音/和弦性质即换季，世界色调与鸟羽色随之变化。
  用户在 HUD 改和声 = 人工干预气候，语义一致。

## 4. Agent 游戏规则

### 4.1 种群 agent（每群一个，本地 LLM）

**输入**（聚合状态 JSON，全部来自现有信号）：centroid、spread、alignment（相位一致度）、
energy、maskingCost（遮蔽度）、pattern 年龄、邻群方位、食物分布、环境广播（昼夜/季节/税）。

**输出旋钮**（映射到现有 Agent Control API，玮圣接口不变）：

| 规则设计稿旋钮 | 我们的命令 | 说明 |
|---|---|---|
| w_sep / w_align / w_coh | `set_motion` 扩展 | 群内三力权重 |
| x_speed_pref（密度档） | `set_density` | 0.25/0.5/1.0/2.0 → 占用栖木比例档位 |
| perch_ratio | `set_density` + 驻留倾向 | 栖息比→长音化 |
| target | `set_anchor` | 迁徙目标（食物/带内） |
| intention | 语义标签 | 记录在 reason，驱动上面旋钮组合 |

**规则集**（≤8 条，按优先级；采用规则设计稿框架，信号替换为我们的）：

| # | 生存规则 | 音乐后果 |
|---|---|---|
| 1 | 安全优先：天敌出现 → 抱团逃离（阶段 2） | 齐奏强音 + 整体滑离 |
| 2 | 饥饿驱动：energy<0.3 且有食物 → 迁徙觅食、降密度 | 走向食物音区的动机迁移 + 变稀 |
| 3 | 稳态：spread 超健康带 → 调聚合/分离 | 音簇宽窄 |
| 4 | 律动维护：alignment 低 → 提对齐，锁相前不动密度 | groove 自我修复 |
| 5 | 能量管理：energy>0.8 且平静 → 提密度；<0.5 → 降 | 力度密度起伏（纯生理） |
| 6 | 生态位守界：非觅食/逃离时质心保持在己方音域带 | 音区稳定、声部分层 |
| 7 | 应答：邻群或用户近期高活动 → 短暂兴奋提速 | call-and-response |
| 8 | 兜底：cruise，小游走 | 稳定持续声部 |

**G7 韧性（在规则设计稿基础上补充）**：这 8 条规则同时以**纯代码确定性策略**实现为兜底。
LLM agent 是「个性层」——同样的规则，LLM 决定倾向与时机；agent 掉线时代码策略无缝接管，
循环永不停。这也让 D1「假策略验证链路」和最终形态共享同一条代码路径。

### 4.2 Master agent（云端强模型）＝ 自然

采用规则设计稿的严格分层：**master 只动环境，永不直接碰种群参数**。
涌现链条：master → 环境 → 种群 agent → 旋钮 → 鸟 → 音符。

master 操作面（对应现有/新增命令）：

| 操作 | 命令 | 音乐后果 |
|---|---|---|
| 投食（位置=某音区附近） | `place_food(x, y, amount)` 新增 | 声部音区迁移、济弱 |
| 能量税 / 丰收 | `set_energy_tax(rate)` 新增 | 全局密度收放、张力-释放 |
| 昼夜周期广播 | `set_daynight(bars)` 新增 | A/B 段 |
| 换季 | `set_scale` 既有 | 移调/和弦色彩 |
| 温度 | `set_bpm` 既有 | 速度 |
| 天敌（阶段 2） | `spawn_predator(x, y, bars)` | 事件性强奏 |
| 指挥模式 | 既有 master 接管路径 | 人类意图→生态操作翻译 |

master 是唯一允许「懂音乐」的环节，但它的输出语言仍是生态操作——规则设计稿此条照单全收。

**调用节奏**（采用规则设计稿实测预算）：种群 agent 每 1–2 bar 一次（bar 边界队列既有），
master 每 4 bar（≈64 tick）一次；强制 JSON 输出（结构化 + 消 CoT，实测 ~46 tok 出 / ~2s）。

## 5. 一体化 zoom：一个世界，一台摄像机

删除第二套鸟群模拟（instrument/boids.js），编排层与声音引擎层统一为**同一世界的两个焦距**：

```
camera = { cx, cy, scale }   // scale 1 = 全景；scale ≈ 1/(3·spread) = 贴群
u = 归一化 zoom 进度（0 = 编排层，1 = 引擎层）
```

1. **单 canvas，所有渲染过 camera 变换**。双击某群 → camera 每帧向该群质心插值并持续跟随
   （群在飞，镜头跟着飞）。
2. **LOD 由 u 交叉淡化**：拉近时扫描线/栖木光晕/其他群淡出（其他群保留为画面边缘暗影，
   世界还在），本群鸟放大显出个体；UI 面板透明度同样由 u 驱动
   （HUD/声部条 ⇄ 运动控制/键盘图）——连续变化，不是 DOM 显隐切换。
3. **同一群鸟**：下潜后引导与运动控制作用于 world 里同一个 flock
   （world.js 增加 per-flock 运动参数覆盖）；8D 关系直接用 world 已计算的那份。
4. **状态机由 u 对齐**：u > 0.5 进入引擎层语义（键盘接管、录音环、隐含接管）；
   u 回 0 自动交还（顺带修复「返回不交还」bug）。音频连续性天然成立。

## 6. 对《规则设计稿》的逐条评审

| 条目 | 结论 | 理由 |
|---|---|---|
| 规则只讲生存，音乐是副产品 | **采用（公理）** | 与本文 §0 判断一致 |
| master 只动环境、三层涌现链 | **采用** | 分层最干净的版本，且 master API 可平滑扩展 |
| 种群旋钮集（权重/密度/栖息/目标） | **采用** | 与现有 Agent Control API 一一映射，玮圣接口不变 |
| 8 条生存规则 + 优先级 + ≤8 约束 | **采用** | 信号源替换为我们的现有聚合量；补代码兜底（G7） |
| 能量/饥饿/食物 | **采用** | `voice.energy` 重定义即可，食物是 master 最好的具象抓手 |
| 昼夜/季节广播 | **采用** | 季节=和声、昼夜=A/B 段，与有机 UI 天然融合 |
| 强制 JSON、本地 vLLM 预算实测 | **采用** | 直接交给 agent 服务侧执行 |
| 停步=长音、栖息比 | **修改采用** | 保留思想，落地为「栖木停驻→力度/时值」（§2） |
| **跨步事件直接发声（时间由鸟速决定）** | **不采用（机制），采用（意图）** | 与已冻结的 G1（采样级节拍精度）、G2（扫描线因果）、和声安全量化直接冲突；改为扫描线保持全局时钟，鸟的运动决定占用/力度/时值——密度涌现的意图完整保留，节拍精度不牺牲 |
| x_speed_pref = 字面鸟速→音符密度 | **修改采用** | 在量化模型下变为「占用栖木比例档位」 |
| 天敌 | **推迟（阶段 2）** | 事件层，基础生态跑通后加；复用斥力点物理，成本可控 |
| 进化（物种形成/灭绝/人工选择） | **黑客松不做（长线）** | 与 4 声部 demo 配置和 PRD 反面清单「无限声部」冲突；列入 L5 长线路标 |
| master 进化选择（fitness 赏罚） | **黑客松不做** | 依赖进化层 |

## 7. 实施阶段

| 阶段 | 内容 | 交付判据 |
|---|---|---|
| P1 | 修「返回不交还」；camera zoom 统一世界（删 instrument/boids.js） | 双击=连续放大跟随，返回=缩出即交还，一套鸟群 |
| P2 | 栖木机制：停驻→发声/力度/时值；引导=编曲 | 赶走鸟→音消失；聚拢→音变强；空群静默 |
| P3 | 能量/昼夜/季节 + agent 规则代码兜底 + 玮圣 LLM 接入 | 无 agent 时循环自呼吸；有 agent 时可见迁徙/觅食 |
| P4 | 食物可视化、天敌事件层、master 环境操作全集 | master 投食→声部迁移可见可听 |
| 长线 | 进化层（物种形成/选择） | 另行预注册 |

## 8. 开放问题

1. 栖木停驻半径 r 与「音不发声」阈值需要试听调参（太敏感则音乐破碎，太钝则生态无感）。
2. 食物的视觉语言（孢子/花/光点）与 bio theme 的统一。
3. 天敌在 4/4 循环中的出现时机是否也应 bar 对齐（倾向：是，惊吓也踩在拍上）。
