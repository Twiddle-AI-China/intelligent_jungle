# 和声-季节重设计：季=和弦，昼夜=色彩（已对齐 2026-07-19）

状态：**旧契约已于 2026-07-22 被产品决策取代**。下文保留为设计沿革，不再作为实现事实。

当前契约：每季固定 8 天；每季有独立四和弦 progression，按天前进一步，第 5–8 天重复第二圈；黎明进入当日和弦，Master 每日显式决定黄昏是否在同一根音上切换色彩，不再昼夜强制换色或抛固定概率。日和弦变化会让 pad/bass 重配并对有音高声部做最近音级迁移。和谐分 H 仍只观测并喂给 Master，不进入 economy 总分。实现与任务状态见 `docs/single-tree-refactor-backlog-2026-07-21.md` §8.2。

## 1. 问题（2026-07-19 江南反馈）

- 现状 `chordForDay`：**每个昼夜**在季进行里走一步 → 天天换和弦、天天家枝迁移，与乐句保持（holdLoops）直接冲突；
- 一季仅 4 天（seasonDays=4，**旧机制已废弃**，现季长 8–16 天由 master 定），季节感和和声段落感都太快；
- 需要 master→sub 的信息契约：master 给什么信息，树 agent 据此做什么音的决策；
- 需要游戏机制：和谐、分数如何闭环。

## 2. 分层和声模型

一句话：**季节 = 一个和弦（和声段落），昼夜 = 同一和弦的色彩明暗**。

| 时间尺度 | 变化内容 | 音乐含义 |
|---|---|---|
| 季（8–16 昼夜，master 定长） | 换根音和弦 = 和声进行走一步 + 最近音级**大迁移**（现 migrateAssignments 只在换季触发） | 段落转换，一年 = 一条四和弦进行 |
| 昼夜（黎明） | 同根音，仅**色彩枝**微调（2nd/4th/6th/7th/9th 内轻移，半音/全音级 voice-leading） | 同一和弦的呼吸明暗 |

五枝分两类（新概念①）：
- **骨架枝**（低 2–3 枝）：root / 5th / octave，整季不动。bass 限低枝 → 整季稳定低音锚；melody 家枝多数日子不迁移 → 乐句保持成立；
- **色彩枝**（高 2–3 枝）：每黎明由 master 从该季色彩盘中选一档，只动这几枝的音。

config 重构方向：现 `progressions[season]`（每季 4 和弦）改为每季 `{ chord: 骨架, colors: [色彩档×3~4] }`——四季串起来就是原来的一条进行（如 春F → 夏C → 秋Am → 冬G 风格可沿用现四季的 major/sus/dorian/minor 质感，做成每季色彩盘）。

换季迁移从"每天的背景噪音"变成稀有事件，配视觉强调（贴图辉光/群飞），正好接替被删掉的晨鸣的仪式位。

## 3. master → sub 通信契约（harmonicFrame）

master 每黎明广播（走现有 dawnPlan 通道，扩字段而非新通道）：

```js
harmonicFrame: {
  season, seasonDay, seasonLength,          // 季节进度（含"还剩几天换季"）
  skeleton: { root, notes: [...] },          // 骨架（整季不变）
  color: { id, notes: [...] },               // 今日色彩档（master 从菜单选）
  tension: tensionRange 内数值,              // 今日张力预算（当前菜单 0.2..0.6）
}
```

master 不直接指定谁唱什么音——它给**和声框架 + 张力预算**，树 agent 在框架内自己选枝（保持"枝=音"的具身性）。各树对 frame 的固定语义：

- **melody 百灵**：tension 低 → 守骨架枝、保持乐句；tension 高 → 允许跳色彩枝、缩短 dwell；
- **pad 斑鸠**：color.notes 加权长音簇选枝（色彩档变化 = pad 的明暗呼吸）；
- **bass 鹈鹕**：只认 skeleton；`seasonDay == seasonLength-1` 时收到换季预告 → 提前聚集，次日黎明领迁移；
- **texture 啄木鸟**：tension 直接映射敲击密度。
