# PRD：鸟群音序器（Flock Sequencer）

> Spark 黑客松核心 demo + 后续产品主线。  
> 技术边界见 [双层架构](two-layer-architecture.md)，排期见 [开发规划](dev-plan-spark.md)。

## 1. 产品定位

**基于多智能体种群协同的音序器**：一个多声部循环乐器，每个声部是一群活的鸟，由 AI agent 演奏；人可以在任何时刻接管任何一群——从宏观编排一直接管到单群内部的音色漫游和键盘演奏。

三个不可妥协的体验支柱：

1. **看得懂**：地图就是钢琴卷帘。X 是循环时间，Y 是音高，扫描线扫到哪、哪里就响。不需要解释「潜空间」用户也能预判声音。
2. **是活的**：鸟群绕着乐句飞。每次循环有细微的 swing 和和弦色彩变化；结构改变时能看到鸟群整体迁徙。
3. **可接管**：agent 演奏与人演奏是同一套控制面。接管不是切换模式，而是把缰绳从 agent 手里拿过来；松手可以还回去。

反面清单（本版明确不做）：自由绘制自动机、无限声部、逐帧 agent 控制、latent 参数面板直接暴露给用户。

## 2. 用户与场景

- **黑客松评委 / 观众**（首要）：3 分钟内看懂「agent 在演奏、人接管后声音跟着人走、下潜后音色随鸟群运动变化」三件事。
- **玩家**（次要，产品主线）：不会乐理的人做出好听的循环；会键盘的人把它当可演奏乐器 jam。

Demo 剧本（验收基准）：

1. 开场：4 个鸟群声部自动循环，master agent 显示当前 BPM/调式；观众看到扫描线与触发闪光对齐。
2. 宏观干预：对 master 说/选「更亮一点、快一点」→ BPM 与调式变化，各声部 agent 在下一个 bar 边界重排乐句，鸟群可见迁徙。
3. 接管：点击 bass 群接管 → 拖动改变乐句位置，音高随 Y 变化，和弦内量化保证不难听。
4. 下潜：双击 lead 群 → 进入单群全屏，拖引导让群收紧/炸开，音色实时变化；接 MIDI 键盘弹一段。
5. 回灌：按「保留乐句」返回上层 → 刚才弹的乐句成为该群 pattern，继续和其他 agent 声部合奏。

## 3. 信息架构与视图

### 3.1 Score View（编排层，默认视图）

- **主画布**：横轴 = 循环时间（默认 4 小节 × 16 步），纵轴 = 音高（master 当前和弦的和弦内音行；各声部音域带用低饱和底色区分）。不画生硬网格线，拍点与音高行用光晕、地形等有机暗示呈现；扫描线自左向右循环。
- **鸟群**：每群 8–24 只鸟，绕自己的 pattern anchor 飞行；扫描线扫过 note group 时该群闪光并发声，制作粒子动画效果。
- **HUD（顶栏）**：苏醒/休眠（播放/停止）、生命节律（BPM）、节律类型（拍号）、和声（根音+和弦性质）、生命周期长度（循环小节数）——界面一律用有机世界词汇，括号内音乐术语只在文档与代码中使用。这些全部是 master 可控项，因此全部可见（「可控才可见」原则）。
- **声部条（侧栏）**：每群一行：音色名、控制方标识（高亮）、mute/solo、电平表、「接管/交还」按钮。
- **agent 存在感**：agent 改变乐句时，目标 anchor 先以幽灵轮廓出现，鸟群飞过去落位——让「AI 在演奏」可见但不弹窗打扰。

交互：

| 操作 | 结果 |
|---|---|
| 点击声部条「接管」 | 该群 controller → USER，agent 暂停 |
| 拖动已接管群 | pattern anchor 整体平移，X 平移=时间偏移，Y 平移=移调（调内量化） |
| 拖动单个 note group | 只改该音符的 beat/音级 |
| 双击鸟群 / 捏合放大到单群 | 进入 Instrument View（隐含接管） |
| 顶栏直接改 BPM/调式 | master controller → USER，master agent 暂停 |
| 「交还」 | agent 恢复控制，以当前 pattern 为新基础 |

### 3.2 Instrument View（声音引擎层，单群全屏）

- 单群鸟全屏漫游（xy-engine 原型形态），背景弱化显示上层循环相位（小型扫描环），保持节拍感。
- **运动 → 音色**：六个运动控制（聚合/对齐/分离/速度/空间/深度）+ 拖拽引导；8D 关系驱动 timbre latent。界面不显示 latent 数值，只显示运动控制——可控才可见。
- **键盘 → 音高**：电脑键盘 `A W S E D F…`（C4–C5）与 MIDI 键盘 note/bend/velocity；无输入时该群按上层 pattern 继续发声（不因下潜而静音）。
- **录音环？？**：始终录制最近 4 小节的演奏 + 关系轨迹；「保留乐句」把量化后的 note 写回上层 pattern，关系均值成为新音色基点；「丢弃」原样返回。
- 返回：缩小手势 / 返回按钮 → Score View。

### 3.3 状态可见性规范

- 每群头顶常驻小徽标（高亮来显示用户控制）；master 状态在 HUD 左侧。
- agent 失联：徽标变灰，声部按最后 pattern 继续循环，不弹错误框。（概率不大）
- 音频后端（pitch-conditioned / pitch-shift）与模型 SHA 显示在设置抽屉，不在主界面。

### 3.4 视觉风格原则

- 整体是**有机世界 / 生物美学**（参考 Synplant 的生物质感），不是工程化的 DAW 界面：无生硬网格线与专业术语，拍点、音高行、音域带都用光晕、地形、萤火等世界元素暗示。
- 触发反馈用粒子动画（扫描线扫过 note group 时闪光+粒子），agent 改乐句用幽灵轮廓+迁徙飞行，避免任何弹窗。
- 视觉参数集中成 theme 配置；黑客松先做一个默认 bio theme，有余力再扩多 theme。

## 4. 音乐性规则

- **和声安全**：一切 Y→pitch 量化到 master 当前和弦的和弦内音；agent 与用户都不能出和弦外音。默认小三和弦，master 可换根音与和弦性质。
- **音域分配**：master 给每群分配不重叠（或弱重叠）的音域带，避免频段打架——先用「音域=频段」的极简规则，不做流式频谱评估。
- **微变化预算**：swing 抖动 ≤ ±1/32 音符；和弦色彩替换 = anchor 音向相邻调内音的低概率（默认 ~10%/循环）借音；音色随群形自然波动。预算值集中在一个配置对象里，可整体调「多活」。
- **结构变化节拍化**：一切大变化（乐句重排、调式切换、段落推进）只在 bar 边界生效。
- **音乐可预测性**： 默认降低鸟群移动速度，音高节奏显著变化每几十秒出现。

## 5. 声部与音色

- 默认 4 声部模板：Bass（低音域带）/ Chord-Pad（中低）/ Lead（中高）/ Texture（高，弱节奏）。
- 音色来源按后端而定：后端 B 时从 14 个已验证音色白名单选；后端 A 训成后从新 riff 音色 Atlas 选；后端 C 时用现有三语料 Species。声部条上的音色选择器只展示当前后端可用集。
- 每群音色基点 = Atlas 上的锚点；instrument view 的漫游在锚点邻域内进行。

## 6. 验收闸门

| # | 闸门 | 通过标准 |
|---|---|---|
| G1 | 节拍精度 | server 端触发抖动 p95 < 5 ms（对 23.22 ms 块） |
| G2 | 因果可读 | 不了解项目的人观看 30 秒后能说出「扫描线扫到鸟就响、越高的鸟音越高」 |
| G3 | 接管即时性 | 接管后第一次拖拽到声音变化 ≤ 1 个 bar |
| G4 | 下潜连续性 | 双击进出 Instrument View，音频不断流、不爆音 |
| G5 | 回灌正确性 | 键盘弹的乐句返回上层后，重放的音高/节奏与演奏一致（量化误差内） |
| G6 | 稳定性 | demo 配置（4 群）连续 30 分钟无 underrun |
| G7 | agent 韧性 | 拔掉 agent 服务，循环继续、界面不报错 |
