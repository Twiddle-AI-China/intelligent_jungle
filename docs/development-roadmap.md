# 分阶段开发与闸门

| 阶段 | 产物 | 硬闸门 |
|---|---|---|
| 0 研究规格 | 哲学来源、三规则、反例、成功/失败定义 | 规则可只靠声音解释 |
| 1 模型 bake-off | BRAVE/RAVE/MRT2 报告、延迟与质量音频 | 6 voices、p95 ≤30 ms、jitter ≤5 ms |
| 2 感知 atlas | 描述符、坏点图、安全邻接图、6 个身份锚点 | 4 个方向盲听正确率 ≥75% |
| 3 规则引擎 | 固定步长、回放、隔离 A/B、遥测 | 目标指标改善且非目标维度不坍缩 |
| 4 macOS Alpha | JUCE standalone、CoreAudio/MIDI、neural worker | 48 kHz 连续 30 分钟无 underrun |
| 5 乐器性测试 | 两轮 5–8 名音乐人测试 | 规则辨认 ≥80%，状态可复现 |
| 6 收敛 | 单世界 6–8 对象、录音与恢复 | 不依赖工程面板即可演奏 |

真实模型质量、多人听测和长时压力测试必须产生实测数据，不能由分析声源或 mock 宣称通过。训练与渲染只在 GPU 服务器 qgpu 队列中执行；权重、语料、atlas、音频渲染和构建产物不进入 Git。
